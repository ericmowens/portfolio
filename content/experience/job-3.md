My first job out of college was at FAST Enterprises. They provide software solutions for state governments, and I had signed on knowing I would be relocating on-site as part of the job. I first relocated to Denver, CO to assist in some development for the core software product, which then gets tailored for each state's needs. I developed and debugged high-quality Unemployment Insurance (UI) software using SQL Server and back-end C#/.NET. During this experience, I had great hands-on experience with code and with some of the strict regulations and requirements that the code needed to handle. I learned some of the specific rules and edge cases which the code had to handle.

In one special task, I created and optimized data report SQL queries returning millions of entries in order to accurately export user data from our software as the customer transitioned to a different software. One aspect of the exported data that stood out was the financial balances of users, as exported data would be used to determine a user's debt or payment owed on the future system. It was crucial that this exported data was accurate. Although many hours were spent focusing on some very specific edge cases in the data, I could not leave out these details. I had a great experience understanding the importance of minor adjustments to SQL query efficiency and accuracy. The query, which would initially take hours to execute, was finalized and I was proud to see it only took a few minutes to return its millions of accurate records.

Eventually, I started to focus on some of the financial management aspects of our Unemployment Insurance solutions. Dealing with financials in software felt like a very sensitive challenge as every amount needed to be accurately accounted for. I relocated to Montpeliler, VT in August 2024 to work on-site with their state Department of Labor. While working on-site using SQL Server and back-end C#/.NET to tailor their UI solution, my team focused on the financial aspect of the software. I discussed clients’ needs for regulations and communicated the full scope of my code changes. It was crucial to understand what changes were needed and how they would impact the users. I regularly presented ideas during code reviews and presented directly to the clients. Some attendees were more experienced in UI law than tech, and I had to make sure that the code functions were properly communicated in those contexts. For example, a user filling out an unemployment insurance form is determined eligible or not eligible for a weekly payment based on their answers. Their answers may also determine that they are only entitled to some portion of their payment. In certain cases, fractions of pennies were deducted and it had to be absoulutely clear which amounts get rounded up or down. These legal factors were crucial to the implementation.

My experience at FAST Enterprises was varied and taught me a lot about how to adapt my code to different contexts. I overcame challenges, both conceptual and technical.
